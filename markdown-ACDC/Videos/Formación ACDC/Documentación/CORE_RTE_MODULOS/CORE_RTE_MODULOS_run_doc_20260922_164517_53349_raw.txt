responsabilidad principal es calcular las primas de seguros basándose en:

6. Introducción a Suscripciones 
El Motor de Suscripciones es un componente especializado del sistema de rating que 
maneja coberturas que requieren ajustes de suscripción a lo largo de su vigencia. Este motor 
permite gestionar operaciones como altas, bajas, modificaciones, suspensiones y rescates de 
suscripciones dentro de una póliza. 
¿Qué es una Cobertura de Suscripción? 
Una cobertura de suscripción es aquella que permite gestionar múltiples ajustes o 
suscripciones individuales dentro de la misma cobertura. Cada suscripción puede tener: 
● Estado (sbnStsVal): AC (Activa), SP (Suspendida), CA (Cancelada) 
● Capital asegurado (cplAmn) 
● Prima anual (preAnm) 
● Número de suplemento (enrSqn) 
● Fecha de efecto y vencimiento 
Ejemplo: Seguro de vida colectivo donde cada empleado es una suscripción independiente 
dentro de la misma cobertura de la póliza colectiva. 
Cuándo se Utiliza 
El motor de suscripciones se activa cuando: 
● Una cobertura está marcada con mcaAjusteSuscripcion == "S" en la configuración 
● Se detectan cambios en las suscripciones entre el suplemento actual y el anterior 
● Se necesita calcular primas y capitales basados en ajustes de suscripción

Jerarquía de Búsqueda 
El sistema aplica una estrategia jerárquica para encontrar las reglas más específicas: 
1. Nivel 1 (Más específico): country + company + branch + product 
2. Nivel 2: country + company + branch + product="99" 
3. Nivel 3: country + company + branch="99" + product="99" 
4. Nivel 4 (Más genérico): country + company="99" + branch="99" + product="99" 
Conditions (Condiciones) 
Las condiciones determinan cuándo aplicar una regla. 
Operadores Soportados: 
Operador Descripción Ejemplo 
EQ Igual a currentFactor == value 
NEQ Diferente de currentFactor != value 
GT Mayor que currentFactor > previousFactor 
GTE Mayor o igual que currentFactor >= value 
LT Menor que currentFactor < previousFactor 
LTE Menor o igual que currentFactor <= value

Token Descripción Ejemplo

Combinaciones de Operaciones 
Combinación Código Método Ejecutado 
S + N + N SNN create() - Alta nueva 
N + N + S NNS modify() - Modificación 
N + S + S NSS modifySuspended() - Modif. suspendida 
N + S + N NSN suspension() - Suspensión


--- [PÁGINA 17 DE 50] ---

Combinación Código Método Ejecutado 
N + N + N NNN compensate() o emptyOperation() 
S + S + N SSN createSupended() - Alta suspendida 
S + S + S SSS createSupendedModify() - Alta susp. con modif. 
* + * + * + RESCATE=S - rescue() - Rescate 
* + * + * + BONOS=S - bonus() - Bono 
Merge de Operaciones 
Cuando múltiples reglas se cumplen, el sistema realiza un merge de operaciones: 
Algoritmo: 
1. Se ordenan las operaciones por cantidad de valores "S" en las acciones principales 
(GENERACION, SUSPENSION, MODIFICACION, RESCATE, BONOS) 
2. La primera operación (mayor prioridad) establece la base 
3. Las siguientes sobrescriben sus valores si tienen "S" 
4. Se usa la implementación de la primera operación 
Ejemplo: 
Operación 1 (3 "S"): GENERACION=S, SUSPENSION=S, MODIFICACION=S, RESCATE=N, BONOS=N 
Operación 2 (1 "S"): GENERACION=N, SUSPENSION=N, MODIFICACION=N, RESCATE=S, BONOS=N 
Resultado: Se ejecuta Operación 1 (más "S")

PARTE VI: MÓDULO COVERAGE PACKAGES 
27. Introducción a Coverage Packages 
El módulo coverage-packages gestiona paquetes de coberturas predefinidos (preferencias). 
Una preferencia es un conjunto de coberturas que se pueden contratar como unidad. 
Funcionalidad principal: 
● Calcular qué coberturas aplican según preferencia solicitada 
● Buscar preferencias que contengan coberturas específicas 
● Aplicar reglas de obligatoriedad y capitales según contexto 
API REST 
Ubicación: com.mapfre.tron.rating.coverage.packages.controller.PackagesController 
Endpoint: Calcular Preferencias

Caso 1: Selección Directa (preferenceId > 0)

Proceso:

2. Carga coberturas configuradas

Caso 2: Búsqueda Inversa (preferenceId = 0) 
Buscar preferencias que contengan coberturas específicas:

Proceso: 
1. Obtiene TODAS las preferencias del ramo 
2. Filtra: verifica si contiene al menos una de las coberturas [1, 3, 5] 
3. Proyección: solo incluye las coberturas solicitadas 
4. Retorno: lista de preferencias coincidentes 
Ejemplo: 
Si existe: 
● Preferencia 1: coberturas [1, 2, 3, 4] 
● Preferencia 2: coberturas [3, 5, 6] 
● Preferencia 3: coberturas [7, 8, 9] 
Buscando [1, 3, 5]: 
● Preferencia 1: mostrará solo [1, 3] 
● Preferencia 2: mostrará solo [3, 5] 
● Preferencia 3: NO se incluye
